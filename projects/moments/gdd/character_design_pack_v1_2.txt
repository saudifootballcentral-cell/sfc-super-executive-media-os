

MOMENTS
Character Design + Lobby Flow Pack
TV as server • phones as controllers • QR join • pre-designed hero roster

PurposeThis pack defines a launch-ready roster of stylized 3D characters, the QR-based join flow, and the TV/phone UX needed to make character selection readable, fast, and party-friendly inside Unity.

1. Character System Vision
All players join the same Moments session by scanning the TV QR code. On their phones they enter a nickname, browse a pre-designed roster, lock a character, and use that same character identity across the main lobby, mini-games, scoreboards, victory moments, and emotes.
Characters are cosmetic-first. They do not change game balance. This keeps mini-games fair while still giving players ownership and attachment.
Design target: readable from across a living room, expressive on a phone screen, simple enough for efficient Unity production, and premium enough to feel like a modern family party title.
Design pillars
Readability
Personality
Production efficiency
Big head / compact body silhouette, bold color blocking, oversized props, face visible at TV distance.
Each hero has a clear fantasy and one anchor prop so players can say “I am the chef” or “I am the astronaut.”
Shared proportions, reusable shader stack, common rig family, modular accessories, animation set reused across the whole roster.

3. QR Join + Character Select Flow
TV lobby shows the Moments logo, animated background, room status, and a large QR code with a short backup URL / room code beneath it.
Player scans the QR code. The phone opens the web controller and binds to the active TV session using a one-time room token.
Phone asks for nickname first so the TV can immediately display “joining…” cards while the player browses characters.
Phone shows the hero carousel with large portrait, name, and one-line fantasy. Swiping changes hero. Tap selects. Hold confirms.
TV updates live with each player card: avatar, name, ready ring, and lock icon. If a hero is already taken, the phone marks it unavailable unless duplicate mode is on.
When everyone is ready, the TV transitions to a lineup moment with all locked heroes before the mini-game vote or intro countdown.

5. Character Production Specification
Area
Direction
Model target
Stylized 3D hero around 10k-18k triangles for the TV build. Shared body topology where possible.
Texture strategy
Single material set per hero where practical: body, face, props. Prefer clean gradients and hand-painted accents over noisy realism.
Rig
Shared humanoid rig with additive facial controls for blink, smile, surprise, angry, laugh. Keep compatibility with common emote set.
Animation pack
Idle, ready, celebrate, lose, point, laugh, clap, shocked, dance loop, mini-game intro pose, podium pose.
Shader look
Soft stylized PBR with bright key light response, subtle rim light, saturated albedo, and controlled specular highlights.
LOD + optimization
LOD0 for close-ups, LOD1 for gameplay, optional impostor or reduced mesh for far lobby crowd shots.
6. Unity Implementation Notes
Create a CharacterDefinition ScriptableObject containing hero id, display name, short fantasy line, rarity tag if used later, portrait sprite, 3D prefab reference, voice pack, emote list, and lock state color.
The TV lobby subscribes to session events: playerJoined, nicknameUpdated, heroHovered, heroLocked, playerReady, playerDisconnected, playerReconnected.
The phone controller uses a lightweight responsive web UI so QR scan friction stays low. Character portraits can be streamed or bundled as optimized WebP / PNG assets.
Keep all character data authoritative on the TV host. Phones send intent only: hover hero, lock hero, unlock hero, ready.
